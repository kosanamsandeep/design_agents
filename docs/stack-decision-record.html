Decision record · historical · superseded 27 Oct 2026

Why this stack — and why not the others

Premise update — internal-only use (27 Oct 2026) This ADR's redistributable licence gate is superseded. Under internal-only use, GPL/LGPL tools and OpenRewrite MSAL recipes are back in scope subject to bank intake; Graphify, CodeGraph, and CodeBoarding are optional. The current plan is the Delivery Plan & Status.

An enterprise, license-clean stack for recovering HLD and LLD from an existing codebase and using them to drive migration. This document records the alternatives we evaluated, the scoring, the license gate, and how the chosen components cooperate end to end.

Original optimisation (now superseded): permissive licensing, verifiable evidence, 1M+ LOC, incremental runs, and a redistributable bundle. The current internal-only baseline is in the Delivery Plan & Status.

Historical: licence-clean premise 6 stacks evaluated Diagrams embedded as SVG · works offline
The original decision — superseded Use Graphify + CodeGraph + CodeBoarding + SCIP/tree-sitter + Structurizr/Mermaid for recovery and design; add Joern for deep data flow and ast-grep + OpenRewrite (Apache-2.0 core) for change. Build the gate layers yourself.
Review correction — OpenRewrite is not uniformly Apache-2.0 The engine and core Java/Groovy/Kotlin bindings are Apache-2.0, but rewrite-spring, rewrite-migrate-java, and the newer language modules (JS/TS, C#, Python, Go, Ruby, Scala, Android) are under the Moderne Source Available License (MSAL). MSAL permits internal use on your own code but prohibits redistribution, bundling into a product, and managed-service use. They are excluded from the redistributable bundle; only Apache-2.0 core recipes are allowed. The earlier “0 commercial” claim was wrong. Under the internal-only premise, MSAL modules are usable internally; see the Delivery Plan & Status.

Three hard constraints eliminate most of the market. The chosen stack is the highest-scoring option that satisfies all three.

Chosen

Graphified evidence + agent synthesis + deterministic change. Every bundled component is MIT or Apache-2.0; MSAL recipe modules are excluded. Every claim is evidence-linked, and migration is verified by an independent oracle.

Rejected on licence

Serena, pyreverse, PlantUML, CodeCompass (GPL); Semgrep, EvoSuite (LGPL); TruffleHog (AGPL); D2 (MPL); Graphviz (EPL); CodeQL CLI (proprietary); OpenRewrite MSAL recipe modules (source-available).

Rejected on fit

Pack-and-prompt, wiki/crawl, single-tool HLD, and agent swarms — each is useful in part, none gives evidence-grounded HLD + LLD + migration.

Default deployment is the baseline, not the full bundle SCIP + tree-sitter, with Joern enabled only for data-flow tasks. Graphify, CodeGraph, and CodeBoarding are candidates, not baseline: each is capability-enabled per repo only after it beats the baseline on a measured metric. Nothing is all-on by default.

01 How we judged the options

Licence is a gate, not a score. A stack that fails the gate is out regardless of how well it scores elsewhere. The remaining criteria are weighted for an enterprise that must run this on large, sensitive repositories.

CriterionWeightWhat “good” means
Licence gatehard gateTop-level bundle is MIT / Apache-2.0 / BSD / ISC; SBOM scan finds no copyleft or unknown transitive dependency.
Evidence quality30%Deterministic facts, provenance for every claim, confidence labels, coverage reporting.
End-to-end fit20%Produces HLD and LLD and a machine-readable model that can drive migration.
Scale15%Handles 1M+ LOC via indexing, partitioning, and incremental re-runs.
Language coverage10%Polyglot support; per-language indexers where precision matters.
Maturity / risk10%Active, stable, auditable; youth risk is acknowledged and mitigated.
Integration & ops10%CLI/MCP/CI integration; reproducible; containerisable; low ops burden.
Cost5%Mostly CPU for facts/graph; LLM cost bounded by incremental runs and caching.

Scores are indicative and deliberately coarse (1–5). They are a communication device for the trade-offs, not a scientific measurement.

LLD layer — SCIP, tree-sitter, CodeGraph

LLD needs exact symbols, call sequences, class/type structure, state transitions, and seams. We build it per bounded context from the deterministic evidence, then let the analyst agent synthesise; the agent never invents members or transitions.

  • Types and members: SCIP definitions + tree-sitter AST.
  • Call sequences: CodeGraph call paths, traced from entry points.
  • Class diagrams: a small tree-sitter → Mermaid generator (replaces pyreverse).
  • States: our own deterministic extractor over enums, status fields, and transition call sites.
  • Invariants and seams: validation sites, interfaces, DI registration, and DB constraints.

The trade we accept

What we give up

  • Serena’s polished LSP ergonomics
  • pyreverse’s one-command class UML
  • Semgrep’s large curated rule set
  • PlantUML’s richer layouts
  • Commercial platform support and SLAs

What we gain

  • A core bundle with no copyleft and no MSAL modules; SBOM-gated
  • Redistribution-safe IP posture
  • Full control of the architecture model
  • Deterministic evidence and reproducibility
  • One integration surface, one eval harness

06 Why you can trust the output

“Incredibly well” is not a prompt property. It is the result of five mechanisms that are deliberately boring.

1 · Evidence or nothing

Every node, edge, flow, and state cites file:line and a confidence label. The critic deletes uncited claims and records them as unknowns.

2 · Independent verification

The critic and verifier run on a different model family. The worker cannot approve its own output.

3 · Frozen outline

The HLD outline is fixed before LLD fan-out. Each context is isolated, with a shared ID space so results merge cleanly.

4 · Reflexion, not vibes

As-is and to-be models are compared explicitly. Convergences and divergences are reported before and after every migration slice.

5 · Evals + human sign-off

F1, MoJoFM, evidence coverage, unsupported-claim rate, and flow recall are measured on maintainer-labeled repos. Boundaries are hypotheses until signed off.

What “done” means

Not “the diagram looks right.” Done means: evidence coverage ≥90%, unsupported claims <5%, top flows validated, and the migration gates green.

06b Pilot, bake-off, and what “measured” means

The architecture is sound but unproven. This is the plan to prove or falsify it before production — and to stop the toolchain from becoming heavier than the evidence justifies.

Production is blocked until the five exit criteria hold The 4.3 score is a design score. The measured score stays empty until the bake-off and golden-repo evaluation are complete.

1 · Define the evidence schema first

One versioned, language-neutral schema: symbols, calls, routes, data stores, components, evidence pointers, and confidence. Stable entity IDs. A written conflict rule for when two tools disagree about an edge — for example, prefer compiler-accurate SCIP over heuristic tree-sitter, and record the losing claim as an alternative rather than silently overwriting it. Build adapters to the schema and treat every tool output as an input, not truth.

Schema draft v1.0.0 — contract tests first Rules, stable IDs, canonicalization, and conflict resolution · JSON Schema 2020-12 · contract tests · semantic validator. 3 valid + 14 invalid fixtures and 14 canonicalization cases pass. v1 is not frozen until SCIP and tree-sitter adapters emit consistent records for the same repository. Hold the schema version, repository commits, golden labels, and evaluation inputs fixed across the bake-off.

2 · Run a bake-off, not a bundle

ExperimentConfigurationQuestionKeep only if

Do not put a graph engine in the baseline while testing graph engines: that measures the benefit of combining engines, not replacing one. Keep the schema version, repository commits, golden labels, and evaluation inputs fixed throughout. Enable capabilities per repo, not all-on by default. Treat CodeBoarding as a boundary proposer, not a truth source; test it on at least one deliberately messy legacy repository, since the supporting evidence comes from two well-organised ones. Pin exact commits for Graphify and CodeGraph, review maintainers, release history and dependency trees, mirror them internally, and run them in a network-isolated container.

Implementation order

  1. Contract tests first: fixtures, stable IDs, evidence requirements, conflict states, malformed references. Freeze v1 only after they pass.
  2. Two adapters: SCIP and tree-sitter on the same small repository; same schema, provenance, and fail-closed behaviour.
  3. Merge + semantic validation: merge equivalent claims, preserve disagreements, apply precedence, run validate_evidence.py after JSON Schema validation.
  4. Bake-off: baseline vs replacement vs combination, on identical commits and labels. Measure incremental value, not node/edge count.

4 · Migration safety, before any write access

Choose the oracle tooling now: characterization tests, contract and schema tests, differential testing where feasible, and mutation testing (PIT for Java, Stryker for JS/TS/C#, equivalents per language). Do not rely on LLM-written tests alone — they freeze current bugs. OpenRewrite (Apache-2.0 core recipes) handles supported semantic recipes; ast-grep handles structural patterns; the agent handles only residue neither can express. Every change is a reviewable, reproducible PR.

  • Enforce gates in CI, not in prose: deterministic preconditions, architecture diff, security scan, rollback plan.
  • Mandatory human approval for high-risk slices; cap the worker's permissions per task.
  • A cross-model critic is one signal, not the oracle. Deterministic checks and behavioural tests carry the decisive weight; a critic from another family shares blind spots.

5 · Close the coverage gaps deliberately

  • Cross-language edges: message topics, RPC, shared schemas — choose a tool or declare out of scope.
  • Stored procedures: PL/SQL, T-SQL, and data-model recovery — choose a tool or declare out of scope.
  • COBOL / mainframe: declare in or out of scope; do not let it silently distort coverage numbers.
  • Runtime traces: mandatory for critical flows, not optional.

6 · Keep it replaceable

Version the schema, skills, recipes, and eval datasets independently of the tools. Add regression tests for every tool upgrade. Keep the method in portable SKILL.md form and the orchestration thin. Make the agent count configurable; replace an agent with a deterministic function wherever it works reliably.

7 · Pilot exit criteria

  1. SBOM and legal review pass on the real bundle, including LLM provider terms.
  2. Each retained tool has a measured, non-overlapping win over the baseline.
  3. Targets are met on all three golden repos, including the messy one.
  4. Incremental runs match a clean re-index and stay within the cost budget.
  5. At least one migration slice completes end to end through every gate, including canary and rollback.

The licence gate in practice

Top-level licences are easy; transitive dependencies are where surprises live. The SBOM scan is the real gate.

    G -- "no" --> D
  • MSAL modules are source-available: internal use is allowed, but redistribution, bundling into a product, and managed-service use are prohibited. Inventory every module; exclude them from the redistributable bundle by default.
  • Allowlist: MIT, Apache-2.0, BSD-2/3, ISC.
  • Maintain THIRD_PARTY_NOTICES.md; Apache-2.0 requires notices and includes a patent grant.
  • Scan the actual installed environment, not just the repositories you cloned.
  • “No conflict” means no copyleft obligations — it does not mean no obligations at all.

Scope
Enterprise HLD/LLD recovery and dependency-ordered migration from existing codebases
Constraints
Licence-clean bundle; verifiable evidence; 1M+ LOC; multi-language; incremental; sensitive code
Decision
Graphify + CodeGraph + CodeBoarding + SCIP/tree-sitter + Structurizr/Mermaid; Joern optional; ast-grep + OpenRewrite (Apache-2.0 core recipes only; MSAL modules excluded) for change; gitleaks + Trivy for security

Corrections after review

  • OpenRewrite: not uniformly Apache-2.0. rewrite-spring, rewrite-migrate-java, and newer language modules are MSAL. Only core recipes are bundled.
  • Scorecard: split into design and measured. 4.3 is a design score; measured is TBD until the pilot.
  • Blueprint: GPL/LGPL/MSAL tools are marked excluded and the stage mapping no longer uses them.

Consequences

Positive

  • No copyleft in the core bundle; MSAL recipe modules excluded and inventoried; the SBOM gate enforces it
  • Evidence-grounded HLD and LLD, not generated prose
  • Machine-readable model that drives migration and architecture diff
  • Portable skills; one versioned plugin; one eval harness

Negative / accepted

  • We build more glue than a commercial platform would require
  • We lose Serena’s and pyreverse’s convenience
  • Two young components need pinning and fallbacks
  • Boundary recovery remains approximate; humans must sign off
  • The measured score is unknown until the pilot; 4.3 is a design score
  • OpenRewrite migration coverage is narrower than assumed because MSAL modules are excluded

Alternatives rejected

  1. Pack-and-prompt — no provenance, fails at scale.
  2. Wiki/crawl — good onboarding, unverified architecture, no LLD.
  3. Single-tool HLD — stops before LLD and migration.
  4. Commercial platform — viable if procured; closed and lock-in.
  5. GPL/LSP-heavy — best UX, fails the licence gate for a bundle.
The durable asset The tools will change. The durable asset is the combination of the evidence schema, the independent critic, the eval harness, and the migration gates. Keep those stable; swap tools behind them when something permissively licensed and better appears.
