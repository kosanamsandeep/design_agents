What is working now — and what is next

SCIP + tree-sitter analytics, a validated evidence model, deterministic HLD/LLD baselines, a CLI, and two read-only synthesis roles — exercised end to end on Apache RocketMQ.

✓ Pipeline runs end to end ✓ Contract tests pass ✓ Merged model validates Measured score: TBD Diagrams embedded · works offline
The one-line status The deterministic foundation works on a 1,550-file Java main-source slice. It is not a production design service yet: boundaries need maintainer sign-off, golden labels are missing, and the synthesis agents are still review-only.

00 What was achieved

Evidence layer

SCIP and tree-sitter adapters emit the same schema; merge preserves evidence and confidence; the semantic validator checks references, coverage, and conflict resolution.

Design layer

Deterministic HLD containers and LLD slices, with evidence pointers, entry points, call-site evidence, surfaces, and explicit unknowns.

Method layer

Portable hld-synthesis and lld-synthesis skills, plus read-only hld-architect and lld-analyst roles.

CLI

scip · treesitter · merge · hld · lld · validate · run.

Contract

Schema v1 draft, 3 valid + 14 invalid fixtures, 14 canonicalization cases; all passing.

Reproducibility

installations.md, index/run scripts, pinned commit, artifact manifest, run record, review outcomes.

03 What the agent reviews found

Two read-only role reviews were run over the generated artifacts. They found real defects, not just style issues. The fixes are in the pipeline, not only in prose.

HLD review

  • Generated/test sources leaked into tree-sitter; namesrv’s witness was a JMH class.
  • Entry points were truncated and dominated by example.
  • unknowns_count did not match the unknowns list.
  • Edge aggregation and witness sampling were undocumented.
  • outline.json, unknowns.json, and hld.md were missing.

What changed

  • Generated/test/build paths excluded; namesrv witness is now main-source.
  • 23 production + 196 example entry points, both reported.
  • Unknowns counts match; all three HLD artifacts are emitted.
  • edge_rule, witness_count, and witness-quality flags added.
  • Module vs container status is explicit: deployable, production.

LLD review

  • 23 of 40 classes came from generated test sources.
  • 45 phantom methods named call.
  • NamesrvStartup was absent; flows cited callee declarations, not call sites.
  • Registration, heartbeat, and route lookup were untraced.
  • Coverage claimed 598 edges while serializing 500.

What changed

  • 34 main-source classes; zero phantom call names.
  • Startup present; every step beyond depth 0 carries call_site evidence.
  • Flows now seed registerBroker, brokerHeartbeat, and getRouteInfoByTopic.
  • Coverage reports edges_total=563 and edges_serialized=500.
  • States, seams, and invariants are explicit; missing ones are unknowns.
Not safe to freeze yet Boundaries, data topology, and runtime flows still need maintainer confirmation and golden-repo measurement. The full dispositions are in agent-review-outcomes.md.

05 Known limitations

  • No golden labels. Overlap is not accuracy; measured F1, boundary F1, and flow recall are still TBD.
  • Java only. COBOL, SQL/PL-SQL, React/TypeScript, and C# are not implemented in this slice.
  • No runtime traces. Dynamic dispatch, DI, and reflection can make static flows incomplete.
  • No data-store/external-system extraction. HLD records this as an unknown.
  • HLD witnesses are samples. 67 files (4.3%) carry container/module-pair evidence; the source model has per-entity evidence.
  • Edge Jaccard is low (0.095). The adapters cover different relations; the union is intentional, but it is not a quality metric.
  • Agents are review-only. The write/refine loop needs a controlled branch, schema validation, and sign-off.
  • Large artifacts are committed compressed. The merged graph, evidence models, and SCIP index are in artifacts/published/*.gz; the HLD/LLD JSON is browsable.
